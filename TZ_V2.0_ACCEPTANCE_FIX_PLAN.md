# 2. Пакеты работ

Приоритет Отчёта §13: P0 = ACC-001…008, ACC-022, ACC-023, ACC-025, ACC-027, ACC-032, ACC-035; P1 = ACC-024 (масштаб — отложен), ACC-026, ACC-028–031, ACC-033, ACC-034, точечные ACC-009…021 по мере попадания в маршрут.

### PKG-A. Домен, гейты и детерминированность — P0 (ACC-001, ACC-002, ACC-004, ACC-006, ACC-029, ACC-032)

- A1 (ACC-001). Гейт «Вернуть робота в парк» в карточке инцидента и в сторе: возврат разрешён только при восстановлении процесса + финальной причине + завершённой сервисной работе с результатом + положительном контрольном запуске. Кнопка disabled с перечнем незавершённых шагов.
- A2 (ACC-006). Permission-гарды на уровне стора `useDemoData` для всех мутаций (действие без права → ошибка, UI кнопки скрывает). Новые права: `incidents.safety` (подтверждение безопасности), `incidents.recover` (возврат робота), наблюдение — `events.create`. Финансовые роли и операционный директор — строго read-only.
- A3 (ACC-002). Централизованные предикаты состояния/очередей инцидента (единая машина состояний) — один модуль, используемый карточкой, списком, «Мой объект», ТОиР. Запрещены локальные копии логики готовности к закрытию/очередям.
- A4 (ACC-004). Детерминированное демо-время живого сценария: действия INC-2026-0033 пишут сценарные метки (открытие 09:12 → назначение резерва → ввод +25 мин → возврат +8 ч 28 мин), а не `Date.now()`. Длительности и деньги воспроизводимы: 25 мин / 29 167 ₽.
- A5 (ACC-032/ACC-004). Убрать псевдо-живой дрейф KPI (`Math.random()` + `setInterval` на Обзоре) и статические фикции («Обновлено 09:15»). Отсутствующие данные не подменяются числами.
- A6 (ACC-029). Убрать отдельную кнопку «Обеспечить безопасность»: безопасность — чек-условие закрытия и запись в истории (подтверждается в шаге регламента при назначении координатора/резерва), не самостоятельное действие с правом у всех.
- Приёмка: e2e «ранний возврат заблокирован», «финансист не мутирует», «25 мин / 29 167 ₽ после живого прогона»; валидатор — 0 ошибок.

### PKG-B. Права, область данных, ТОиР-вход — P0 (ACC-005/019, ACC-007)

- B1 (ACC-007). Объектовая область на всех экранах: `ReportsPage` под `useTenantScope`; deep-link карточки (инцидент/робот/объект/зона) вне области роли → редирект со штатным объяснением.
- B2 (ACC-005/019). Домашний экран SERVICE_ENGINEER — очередь ТОиР «мои работы» (исполнитель = текущий пользователь), представления «ожидает/в работе/ожидает запчастей/контрольный запуск». Раздел «Сервис и ТОиР» — в навигацию сайдбара.
- Приёмка: e2e SITE_MANAGER не видит чужие объекты в Отчётах; SERVICE_ENGINEER попадает в свою очередь.

### PKG-C. Единые метрики — P0 (ACC-023, ACC-016)

- C1. Модуль `src/data/metrics.ts`: единые селекторы техдоступности, операционной доступности мощности, потерь, MTTR с фиксированной формулой и периодом набора (30 дней; плановый фонд = роботы × 8 ч × 30 дней = 6 240 робот-ч). Все страницы (Обзор, Аналитика, списки/карточки роботов и объектов, Отчёты) считают только через него. Период и источник видны рядом с числом.
- C2 (ACC-016). Сводка объекта: раздельно операционное влияние / техническая недоступность / денежные потери; формула потерь в подсказке. Совпадение с реестрами гарантировано единым селектором.
- Приёмка: e2e «одинаковые KPI на всех экранах» (робот в списке = робот в карточке; объект в списке = карточка = аналитика).

### PKG-D. Ролевые главные страницы — P0 (ACC-022, ACC-025, ACC-026, ACC-027)

- D1. Роутинг по роли после входа: SITE_MANAGER → «Мой объект» (есть); FLEET_OPERATIONS_MANAGER / SERVICE_MANAGER → новая «Портфель роботизации»; OPERATIONS_DIRECTOR + FINANCE_MANAGER → новая «Экономика эксплуатации»; SERVICE_ENGINEER → очередь «Мои работы» (B2); SYSTEM_ADMIN / SHIFT_OPERATOR → Обзор.
- D2. «Портфель роботизации» (Отчёт §10.4): вердикт портфеля, ключевые показатели (техдоступность, операционная доступность, MTTR, повторные, бэклог, потери), карточки объектов с сортировкой по критичности, системные причины (повторяемые на ≥2 объектах), очередь решений. Переходы «портфель → объект → зона → робот → инцидент» с сохранением периода.
- D3. «Экономика эксплуатации» (Отчёт §10.5): потери за период, Δ к предыдущему периоду, объекты с максимальными потерями, доля подтверждённых расчётов, очередь финансово-операционных решений; каждая сумма раскрывается до простоев/ставки/формулы. Только подтверждённые потери; TCO/окупаемость/эффект план-факт отсутствуют (нет базы — не подставляются). Роль строго читающая (A2).
- D4 (ACC-025). «Мой объект»: вердикт из состояния зон (не из случайных KPI), кликабельность всех показателей и блоков внимания в точный срез.
- Приёмка: e2e трёх ролевых главные; ручной прогон ролей по Отчёт §12.
