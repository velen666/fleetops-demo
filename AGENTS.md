# FleetOps Demo Agent Rules

## Repository Role

- Этот репозиторий — **автономный демонстрационный стенд** FleetOps (далее «демо»): статическое Vue 3 SPA без backend, без API-коннекторов, с детерминированным генератором демо-данных.
- Назначение: воспроизведение пользовательских сцениев и управленческих срезов из технических заданий (ТЗ) для показа заказчикам. Демо не является продуктовым кодом FleetOps и не заменяет `fleetops-frontend`.
- Источник требований: `ZIMA_FleetOps-ТЗ_v2.0_на_доработку_демо-стенда.md` (актуальная итерация) и план переработки `TZ_V2.0_REWORK_PLAN.md`; приёмочный маршрут — `ZIMA_FleetOps-общий_сценарий_демонстрации_и_приёмки_демо-стенда_v1.1.md`. Предыдущие ТЗ (v1.4/v1.5/v1.6) и `TZ_V1.6_PLAN.md` — реализованная база и исторический контекст.
- Коммитить изменения демо из этого репозитория; ветка `master`, remote `origin`.

## Demo Architecture

- **Стек**: Vue 3 + TypeScript + Vite, shadcn-vue (reka-ui), Tailwind v4, Chart.js, pinia, vue-router.
- **Данные**: `src/data/generator.ts` — единственный источник демо-данных (инциденты, роботы, объекты, события, простои, работы ТОиР). Никаких API-вызовов; всё вычисляется локально при старте и хранится в pinia-сторе (`useDemoData`).
- **Русские подписи**: `src/data/labels.ts` — единственное место перевода машинных кодов (статусы, причины, типы) на русский. Машинный код допустим только как вторичный текст.
- **Роли**: `src/data/roles.ts` — 8 демонстрационных ролей с permission-наборами; логин — выбор карточки роли (без реальной аутентификации).
- **Страницы**: `src/pages/*` — Обзор, События, Инциденты, Карточка инцидента, Простои, Аналитика, Роботы, Объекты, ТОиР, Отчёты.

## Data Invariants (обязательные инварианты генератора)

Требования ТЗ v1.6 (раздел «обязательные инварианты») проверяются юнит-валидатором и должны выполняться всегда:

- Хронология: событие ≤ создание инцидента ≤ назначение координатора ≤ уточнение причины ≤ её подтверждение ≤ подтверждение восстановления ≤ закрытие. Второе событие не раньше первого.
- Интервал простоя: конец ≥ начала; длительность вычисляется из временных меток в минутах и одинакова во всех экранах; открытый интервал не показывает `0,0 ч`.
- Экономика: потери = подтверждённые часы × ставка объекта; одно правило округления во всех экранах.
- Закрытый инцидент обязательно имеет финальную причину, комментарий человека, подтверждённое восстановление и решение по простою (включая явное «недоступности не было»).
- Источники: WMS передаёт только процессные события; технические сигналы — от RMS/FMS/RCS или контроллера; ручное подтверждение — отдельный тип доказательства.
- Канонические идентификаторы: `INC-2026-XXXX` везде (внутренний адрес `inc-XXX` пользователю не показывается); один робот — один ID (`FMR-001`, не `FMR-1`); одна зона на всех вкладках.
- CA-014 «Ошибка конфигурации» запрещена как универсальная причина: только техническая подкатегория с параметром, версией, логом и исправлением.

## Design System

- [DESIGN.md](DESIGN.md) — обязательный design spec демо (общий с продуктовой темой: glassmorphism dark-first, 4 палитры, 3 уровня токенов в `src/assets/styles/style.css`).
- Новые компоненты используют только design-токены; hardcoded HEX запрещён. Статусные цвета — только через `--status-*`. Числовые плитки — `tabular-nums`.
- Glassmorphism (`backdrop-filter`) только для карточек верхнего уровня, хедера, модалок и сайдбара — не для ячеек таблиц и рядов списков.

## UI Source of Truth

- Интерактивные элементы строятся только на shadcn-vue (`src/components/ui/*`); нативные `<button>/<input>/<select>/<table>` для пользовательского UI запрещены. Инвентарь: [SHADCN_COMPONENTS.md](SHADCN_COMPONENTS.md).
- Русский язык — основной текст интерфейса; англоязычные машинные статусы (HIGH, CLOSED, CONFIRMED, OPERATIONS, IT …) пользователю не показываются — только через `labels.ts`.

## Execution

- Перед коммитом: `pnpm lint`, `pnpm format:check`, `pnpm type-check` — все чистые; `pnpm build` собирается без ошибок.
- Данные: любое изменение `generator.ts`, влияющее на набор, сопровождается прогоном валидатора (`pnpm test`) — ноль ошибок по хронологии, обязательным полям, источникам, идентификаторам, длительностям и экономике.
- Изменение UI проверяется вручную в браузере (`pnpm dev`, порт 5180): маршрут, сценарий, наблюдаемый результат фиксируются в коммите/плане.
- Коммит-месседжи: `demo: <суть>` или со ссылкой на пакет плана, например `demo: A2 — redistribute CA-014`.
- Не коммитить: node_modules, dist, локальные артефакты, скриншоты вне `docs/screenshots`.
