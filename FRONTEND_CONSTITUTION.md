# FleetOps Demo Constitution

Локальная конституция демонстрационного стенда `fleetops-demo`. Продуктовые конституции (`fleetops-frontend/docs/FRONTEND_CONSTITUTION.md` и др.) на демо не распространяются: у демо нет backend, API-контрактов, Zod-парсеров и продуктового RBAC.

## 1. Основное решение (Core Decision)

Демо — **статическое SPA с детерминированным генератором данных**. Единственный источник истины для экранов — `src/data/generator.ts` и производные вычисления. Вся аналитика (агрегаты, топы, повторяемость, доступность, потери) вычисляется из одного набора данных, поэтому любой показатель обязан раскрываться до исходных инцидентов, а суммы на всех экранах совпадают.

## 2. Архитектура Vue

- Vue 3 `<script setup lang="ts">` + Composition API; состояние — pinia (`stores/`), данные — `useDemoData()`.
- Страницы в `src/pages/`, переиспользуемые блоки в `src/components/`, shadcn-канон в `src/components/ui/` (не редактируется вручную, только регенерация CLI).
- Маршрутизация `vue-router` с `createWebHistory`; состояние фильтров значимых реестров (инциденты, простои, аналитика) хранится в query-параметрах, чтобы прямая ссылка и возврат сохраняли выборку.
- Lazy-загрузка страниц через `import()`; при ошибке загрузки модуля — понятное сообщение и кнопка перезагрузки, не пустой экран.

## 3. Модель данных (демо)

- Доменные типы — `src/types/domain.ts`; справочники (типы, причины, зоны ответственности) — там же или в `generator.ts`.
- Инварианты данных (хронология, источники, идентификаторы, длительности, экономика, закрытие) обязательны и проверяются валидатором в `src/data/*.test.ts` (vitest). Изменение генератора без зелёного валидатора запрещено.
- Причина инцидента — самостоятельная сущность: объект воздействия, механизм отказа, доказательства, зона ответственности, корректирующее действие. Тип инцидента («что наблюдаем») не подменяет причину («почему произошло»).
- Источники событий типизированы: RMS/FMS/RCS (технические), WMS (только процессные: задание не выдано/не принято/прервано/не выполнено), ручное подтверждение (человек, роль, время).
- Интервал простоя — отдельная сущность со статусами «Открыт / Ожидает подтверждения / Подтверждён / Скорректирован / Отклонён», характером простоя и объектом недоступности; статус закрытия инцидента не используется как статус интервала.

## 4. Русский язык и подписи

- Пользовательские статусы, роли, зоны ответственности и причины отображаются по-русски через `src/data/labels.ts`. Машинный код — вторичный текст (подсказка/technical detail).
- Формулировки карточки — человеческие: «Наблюдение: правый привод отключён защитой», «Причина подтверждена — кто, когда, на основании чего», а не «IT-002 / FINAL».
- «(авто)» в истории — только у действительно системных действий; ручные записи содержат пользователя, роль, время и основание.

## 5. Экономика и показатели

- Потери = подтверждённые часы × ставка объекта; одно правило округления (`Math.round` до рубля) во всех экранах.
- Доступность парка = 1 − подтверждённый простой / плановый фонд робот-часов (24×7 × парк × период); рядом показываются числитель и знаменатель. Текущая техническая готовность = роботы «готов/работает» / весь парк — отдельный показатель.
- Слово «SLA» не используется, пока не настроены нормативы; блок называется «Время реакции и восстановления» с явными формулами.
- Отсутствующая сумма — это отсутствие (не `0 ₽`, не прочерк без пояснения); `0 ч, процесс компенсирован` — допустимая явная формулировка.

## 6. Переходы и проверяемость

- Любой агрегат (плитка, столбец диаграммы, строка топа) — точка входа в детализацию: переход открывает отфильтрованный реестр/диалог, итог выборки равен агрегату, возврат сохраняет фильтры и позицию.
- Диалоги детализации — полноширинные (до 90% / 1200 px), читаемые на 1366×768 без горизонтальной прокрутки; на узких экранах таблица превращается в карточки.
- Индикатор загрузки при переходах; фильтры в URL; прямые ссылки стабильны.

## 7. Верификация

- Статика: `pnpm lint`, `pnpm format:check`, `pnpm type-check`, `pnpm build` — обязательно чистые.
- Данные: `pnpm test` — валидатор всех инцидентов/интервалов/агрегатов, ноль ошибок.
- UI: ручной проход ключевых сценариев ТЗ (ДТП; палеты; лидар; очередь разбора → полный цикл) в браузере на :5180 с фиксацией результата в плане.
- Сборка для показа: `pnpm build` + `pnpm preview` (собранные статические ресурсы, не исходные `.vue`-модули).

## 8. Do Not Change

- Не добавлять реальный backend/API-вызосы, аутентификацию и продуктовые коннекторы — демо остаётся автономным.
- Не менять shadcn-канон `src/components/ui/` вручную.
- Не выводить пользователю внутренние адреса (`inc-001`) и англоязычные статусы.
- Не размножать источники правды: агрегаты считаются из одного набора данных, подписи — из одного `labels.ts`.
